# AI-Health-Companion-Band
AI-powered personal health companion band using ESP32-S3, TinyML, multi-sensor health monitoring, and secure cloud connectivity.
# Personal Health Companion — ESP32S3 Setup (SIH26181)

## Folder must contain exactly these 4 files together:
```
PersonalHealthCompanion/
├── PersonalHealthCompanion.ino
├── model_hr_final.h
├── model_resp_final.h
└── model_spo2_final.h
```
The 3 `.h` files come from Niladri's Jupyter working folder (generated by the
training notebook, `SIH2026FINAL.ipynb`, Cell 42/43) — copy them from there
into this same folder as the `.ino`.

## Arduino IDE — Library Manager, install these:
- ArduinoJson (Benoit Blanchon)
- Adafruit GFX Library
- Adafruit SSD1306
- DHT sensor library (Adafruit)
- Adafruit Unified Sensor
- OneWire
- DallasTemperature
- Adafruit BMP280 Library
- SparkFun MAX3010x Pulse and Proximity Sensor Library
- arduinoFFT (Enrique Condes)

Do NOT install TensorFlowLite_ESP32 — it is not used in this version.

## Board settings
- Board: ESP32S3 Dev Module (or your specific board variant)
- Upload the sketch as usual (Verify -> Upload)

## After flashing
- Serial Monitor @ 115200 baud — should print "Setup complete."
- OLED will show 4 pages (button on GPIO11 cycles): Vitals, Environment,
  AI Status, AI Suggestion
- Vitals/Suggestion pages populate only after the first full 8-second
  sensor window is captured (finger must stay on the MAX30102, ECG
  electrodes must be attached) — expect ~8s delay after boot before
  HR/Resp/SpO2/Stress show real numbers instead of "--"
- Wi-Fi AP: SSID "HealthCompanion_AI", password "health1234" — connect
  and open http://192.168.4.1 for the live dashboard

## What happens end-to-end
Sensors (MAX30102 PPG + AD8232 ECG) → 8s raw buffer → on-device feature
extraction (C code, no cloud) → 3 Random Forest models predict HR/RESP/SpO2
→ stress computed from HRV → rule engine picks the single most urgent
message → shown on OLED + buzzer/vibrator alert if critical.
